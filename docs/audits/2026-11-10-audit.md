# Audit: pi-claude-bridge

- **Date:** 2026-11-10
- **Commit:** `c2b6eeebbe4a148f7794d664d35a05ba3b29ea4f` (the merge of PR #39 on `main`)
- **Scope:** the whole repo: `src/` (read in full), `tests/`, `diag/`, `docs/`, CI and release workflows, `package.json`.
- **How it was checked:** every finding was read in the code. Those marked *reproduced* were also run in a throwaway probe outside the repo. Baseline on the lockfile versions: `npm run typecheck` passes, `npm run test:unit` passes 552 of 552.

What this repo does: It is an extension for the `pi` coding agent. It lets pi use Claude through a Claude Code subscription: Claude Code talks to Anthropic, pi runs every tool, and the bridge keeps a copy of pi's conversation in Claude Code's session files so the prompt cache (the saved, cheaper part of a request) stays warm.

Load assumed: one developer on one machine. One process serves several pi sessions at once (a parent and its subagents), and several pi windows can share the same files on disk.

## Must fix

1. **A project file holding `null` stops the extension from loading** (`src/config.ts:L46-54`, `L111-119`)
   - **What this is:** `loadConfig` reads the global config and the project's `.pi/claude-bridge.json`. The project file is treated as untrusted, so a cloned repo cannot change options.
   - **Problem:** *Reproduced.* A file with the content `null` is valid JSON, so `tryParseJson` returns `null`, and `project.startupNoticeShown` throws `TypeError: Cannot read properties of null`. Any cloned repo can ship that file; the same happens with a global file holding `null`.
   - **Fix:** In `tryParseJson`, return `{}` unless the parsed value is a plain object (not `null`, not an array). Add one test for it in `tests/unit-config.mjs`.
   - **If we skip it:** Opening pi in such a repo gives no Claude models at all, with an error that does not point at the file.

2. **The safety tests run against pi 1.2.0, but pi is at 1.5.1** (`package.json` devDependencies, `package-lock.json`, `tests/unit-pi-streamfn-inventory.mjs`, `tests/unit-prompt-guard.mjs`)
   - **What this is:** Two tests read pi's installed code to warn when pi changes something the bridge depends on: which pi modules can call the provider, and how pi's system prompt opens.
   - **Problem:** *Reproduced.* The lockfile pins pi 1.2.0, so CI checks an old pi. With pi 1.5.0 installed, both tests fail (`agent-session.js: 2 -> 5` call sites; "pi reworded its preamble") and `tsc` reports 3 type errors (`src/index.ts:1266`, `3024`, `3098`).
   - **Fix:** Bump the three `@earendil-works/pi-*` devDependencies to the current release. Then read the three new call sites and update the inventory, point the preamble test at the 1.5 wording, and fix the three type errors.
   - **If we skip it:** A new pi code path can reach the bridge with a prompt it never recorded. That is how branch summaries once failed turns, and today nothing warns about it.

3. **The answer text appears twice when a turn arrives without stream events** (`src/index.ts:L1770-1783`)
   - **What this is:** At the end of a turn, the bridge adds the final result text if no assistant message delivered it.
   - **Problem:** *Reproduced.* The check is "no stream event was seen", not "no text was delivered". An assistant message with the text "hello" followed by a success result gives two "hello" blocks. This is the case when Claude Code falls back to a non-streaming request before the first stream event; how often that happens was not measured.
   - **Fix:** Change the guard to "no text block in this turn yet": `!queryCtx.turnBlocks.some((b) => b.type === "text")`. Add the two-message case to `tests/unit-nonstreaming-fallback.mjs`.
   - **If we skip it:** After a stalled connection, pi shows and stores the answer twice, and the copy is sent back to the model on later turns.

4. **A failed rebuild deletes the Claude Code session file and leaves nothing** (`src/index.ts:L899-917`)
   - **What this is:** A rebuild rewrites Claude Code's session file from pi's history, keeping the same id.
   - **Problem:** *Reproduced.* The old file is deleted at L904, before the new content is converted (L912) and saved (L913). If the conversion throws (for example a tool call named `mcp__custom-tools__bash` in history, `src/convert.ts:L50`) or the save fails (full disk), no file is left and the state still points at the deleted one.
   - **Fix:** Run the conversion (`convertPiMessages` and `repairToolPairing`, both pure) before `deleteSession`, so bad input throws while the old file still exists. If `save()` throws, clear the session state.
   - **If we skip it:** The `@file` attachments carried from the old file are lost for good, and with a bad history entry every later turn deletes and fails again.

## Should fix

5. **AskClaude's second call does not see the newer turns** (`src/index.ts:L2612-2624`)
   - **What this is:** AskClaude with `isolated: false` is meant to give Claude the whole conversation.
   - **Problem:** *Reproduced.* Once a session exists for the pi session, the code resumes it as is. A second AskClaude call, six turns later, resumes the file from the first call; the later turns never reach Claude. The comment says the provider already caught up, but AskClaude only runs when another provider is active.
   - **Fix:** Delete the `if (askClaudeState)` branch and always call `syncSharedSession`, which already reuses the session when nothing was missed and rebuilds it otherwise. About 5 lines less.
   - **If we skip it:** Claude answers from an old view of the conversation and nothing shows it. AskClaude is deprecated and off by default, which limits who is hit.

6. **Resuming after an abort throws away the saved fork points** (`src/index.ts:L1960-1962`, `src/fork.ts:L587-596`, `L714-721`)
   - **What this is:** After each finished turn the bridge saves where Claude Code's file ended, so a later `/fork` can start from that point and keep the cache.
   - **Problem:** *Read, not run.* `resumeAfterAbort` deletes the whole mirror file to clear the abort mark. The next save finds no earlier record, so only the new turn is kept. A `/fork` to any turn before the abort finds no fork point and rebuilds the whole conversation. The error-retry path does the same.
   - **Fix:** Instead of `dropMirror`, rewrite the mirror without the abort fields and keep `turns`. Add a test: ten turns, an abort, a resume, then a fork at turn five.
   - **If we skip it:** One Esc in a long session makes every later `/fork` to an earlier point pay for the whole conversation again.

7. **CI never runs the type check, and a push to main runs nothing** (`.github/workflows/ci.yml:L3-5`, `L24`; `.github/workflows/release.yml`)
   - **What this is:** CI runs the unit tests on pull requests. The tests run through `tsx`, which strips types without checking them.
   - **Problem:** `npm run typecheck` exists but no workflow calls it, and CI does not trigger on a push to `main`. A type error or an unused import in a pull request passes CI and is published; `src/usage.ts` already tells of a wrong field name that hid this way.
   - **Fix:** Add `- run: npm run typecheck` to both workflows and `push: branches: [main]` to the CI triggers. It passes today on the lockfile versions.
   - **If we skip it:** Type mistakes reach npm, and the first sign is a user report.

8. **A session stays "owned" by a window that already left it** (`src/fork.ts:L603-610`, `L678`, `L689`, `L829`)
   - **What this is:** The mirror file records the pid (process number) of the pi process that last used a session, so two live processes do not write the same Claude Code file.
   - **Problem:** *Read, not run.* Ownership is never given up and is checked by pid alone. Window A works on session S, then switches to another session; opening S in window B rebuilds it, because A is still alive. After a reboot, a pid reused by any other program blocks the resume the same way. The Claude Code child is already checked with pid plus start time; pi's own pid is not.
   - **Fix:** Store `startTime: cliStartTime(process.pid)` in the mirror and replace the three `processAlive(record.pid)` checks with `cliAlive(record.pid, record.startTime)`.
   - **If we skip it:** Reopening a session in a second window pays for the whole conversation again, with no visible reason.

9. **`@file` attachments are lost after any turn with two user messages** (`src/attachments.ts:L105-134`)
   - **What this is:** On a rebuild, the file contents Claude Code expanded from `@file` are put back next to the prompt that named them. Prompts are matched by their position in the conversation.
   - **Problem:** *Reproduced.* Claude Code stores a turn with two user messages as one record ("A\nB"), while pi has two messages. After such a turn every position is off by one, the text check fails, and each later attachment is dropped as "changed". The same turn with one message on both sides works.
   - **Fix:** Match by text: take the first unused pi prompt at or after the stored position whose text equals the stored one.
   - **If we skip it:** In sessions with a steer or a follow-up, Claude silently loses the files it was given after the next `/compact` or branch switch.

10. **The mirror file uses a shared temp name and open permissions** (`src/fork.ts:L587-596`)
    - **What this is:** `saveMirror` writes a temp file, then renames it over the real one.
    - **Problem:** *Read, not run.* The temp name is the same for every process, so two windows saving the same session can leave a half-written file, which then reads as "no mirror". The file is also created with default permissions, although it can hold the full text of an aborted prompt. The capture store next to it already uses a per-process temp name and owner-only modes.
    - **Fix:** Use `${file}.${process.pid}.tmp`, `mode: 0o700` on the directory and `mode: 0o600` on the file, as `src/prompt-capture-store.ts:L153-157` does.
    - **If we skip it:** A rare lost mirror (a full rebuild), and prompt text readable by other users on a shared machine.

11. **The log audit scripts read the wrong log** (`diag/audit-warnings.mjs:L44-48`, `diag/audit-cache.mjs:L60-64`, `diag/attrib.py:L110-111`)
    - **What this is:** These scripts scan the bridge's debug log for warnings and cache misses.
    - **Problem:** Their comment says "same resolution as `src/log-paths.ts`", but that file gives priority to `CLAUDE_BRIDGE_DEBUG_PATH` and the scripts never read it. `attrib.py` also ignores `PI_CODING_AGENT_DIR`. Someone who moved the log gets a scan of the old default log.
    - **Fix:** Use `process.env.CLAUDE_BRIDGE_DEBUG_PATH || join(agentDir, "claude-bridge.log")`, and the same in the Python script.
    - **If we skip it:** The audit prints "clean" for a log that is not the one in use.

12. **`attrib.py` credits results to the wrong query** (`diag/attrib.py:L85-93`)
    - **What this is:** The script pairs each "fresh query" log line with its outcome. The numbers in `diag/EXTRA-USAGE-400.md` come from it.
    - **Problem:** It closes a query on a `result: served` line and again on `for-await loop exited`. The bridge logs `served` before the error line (`src/index.ts:L1700`, then `L1712`), so a failed query is closed as "ok" and its error finds nothing to mark. With a nested subagent query, the child's exit line closes the parent. Not confirmed: whether a failed result always carries the model usage that prints the `served` line.
    - **Fix:** Ignore `result: served`. On the error line, mark the top query without closing it. Close only on `for-await loop exited`, which appears once per query.
    - **If we skip it:** Failure rates from the log come out too low, and decisions rest on them.

13. **Two copies of "mark notice shown", both writing the config in place** (`src/config.ts:L73-109`)
    - **What this is:** Two functions record in the global config that a one-time notice was shown.
    - **Problem:** They are the same except for the field name, so any fix must be made twice. Both rewrite the user's config with a plain `writeFileSync`, which empties the file first: a pi process starting in that moment reads a broken file and runs with no `provider` settings.
    - **Fix:** One `markNoticeShown(field)` that writes to a temp file and renames it. About 17 lines less.
    - **If we skip it:** Rarely, one window runs a whole session without the user's plan or Claude executable path.

## Nice to have

14. **False "malformed JSONL" warning for an empty session** (`src/session-verify.ts:L23-36`)
    - **What this is:** After writing a session file, the bridge checks it and warns the user if something is off.
    - **Problem:** *Reproduced.* With zero records expected and an empty file, the count check passes and `JSON.parse(lines[0])` throws on `undefined`. This needs a history where every message is filtered out, which is hard to reach.
    - **Fix:** Add `if (lines.length === 0) return warnings;` after the count check.
    - **If we skip it:** A user may be asked to open an issue about a file that is fine.

15. **Thinking text can arrive empty when no effort level is sent** (`src/index.ts:L2341`, `L2654`)
    - **What this is:** The bridge asks Claude Code for summarized thinking, because newer models hide thinking text by default.
    - **Problem:** *Read, not run live.* It asks only when an effort level is set. Six models in pi's catalog mark "off" as unsupported (they always think): with thinking off in pi, no effort is sent, thinking stays on, and the text is hidden.
    - **Fix:** Set the argument whenever thinking is not disabled: `if (model.reasoning && thinking?.type !== "disabled")`.
    - **If we skip it:** Empty thinking blocks on those models.

16. **AskClaude starts Claude Code even when the call is already aborted** (`src/index.ts:L2666-2696`)
    - **What this is:** AskClaude checks the abort signal after creating the query.
    - **Problem:** The SDK starts the Claude Code process inside `query()`. With an already-aborted signal the code only asks for an interrupt and throws before the `try/finally` that closes the query.
    - **Fix:** Check `signal?.aborted` and throw before calling `askClaudeQueryImpl`.
    - **If we skip it:** A stray Claude Code process may be left behind after an aborted call.

17. **`npm test` dies silently when a test variable is missing** (`tests/lib/bash-setup.sh:L61-69`)
    - **What this is:** `require_env` prints an error and exits when a variable is not set.
    - **Problem:** *Reproduced.* It is called as `V=$(require_env NAME)`, so the error goes into the variable. The script exits with code 1 and prints nothing.
    - **Fix:** Send the message to stderr: `echo "ERROR: ..." >&2`.
    - **If we skip it:** A new contributor gets a failed run with no hint.

18. **Stale notes and leftovers** (`src/index.ts:L804`, `L956`; `TODO.md`; `docs/reference.md:L67`)
    - **What this is:** Comments and docs that describe the code.
    - **Problem:** A comment cites `tests/exp-session-clear.mjs`, which does not exist. `__test.getHistoryRewritten` is used nowhere. `TODO.md` lists as open two items the code already does (`isReentrant` is passed; the Claude Code process exit is tracked). The docs name only `CLAUDE_BRIDGE_TESTING_ALT_MODEL`, but the tests also need `..._ALT_PROVIDER`.
    - **Fix:** Delete the dead reference, the unused hook and the done TODO items; add the second variable to the docs.
    - **If we skip it:** Readers chase a test that is gone and work that is done.

Left out: 3 smaller ones (a session start that clears every session's state in a multi-session process, unconfirmed; two small maps that grow by one short entry per session; two untested low-risk helpers).

Checked and dropped: two reports that an abort could be shown as an error. The SDK ends the message loop normally after `close()`, so that path is not reached.
